# Semantic Bridge 精确目标训练（实验功能）

这套流程训练文本条件表示之间的 Semantic Bridge，不训练视频 LoRA，也不更新 H3 视频模型或文本编码器。当前目标函数仍是实验方案，尚无经过最终视频验收的有效模型；训练 loss 降低、权重成功加载、合成测试通过，都不能证明视频效果提高。

公共入口：

- `tools/build_sentence_targets.py`：从原生 X/Y 文本表示、原生 token 和精确句段构建监督目标。
- `tools/fit_explicit_targets.py`：只读取显式列出的 train 样本；默认 dry-run，添加 `--execute` 才进行 CPU 优化。

需要仓库及其 Python 依赖（NumPy、PyTorch、safetensors）。使用已安装这些依赖的 Python；两个脚本均从自身位置定位仓库，可在其他工作目录调用。以下路径都是示例相对路径，不含预置模型、私人缓存或训练数据。

## EXE 图形入口：拟合已构建的目标

使用包含此更新的启动器，选择“实验：显式句段目标拟合（CPU，仅语义桥）”。先按下文用 builder 构建目标和 `explicit_train_target_manifest_v1` 清单，再在 GUI 选择 Python、显式 train 目标清单和**尚不存在**的新输出目录。清单须为 `evidence_class=train_fit_probe`；合成 fixture 只用于测试。无需填写 ComfyUI、编码器、旧聚合 NPZ 或旧分组字段。界面不自动编码或判断目标视频质量。

“检查目标”只执行公共 fitter 的 CPU dry-run，核对明确列出的文件、哈希和 train 数组，不创建模型、优化器或训练输出。“开始训练”先执行相同 dry-run，再用同一份清单 SHA 和同一组参数执行拟合；文件或参数变化会中止。清单中的相对路径仍相对各自清单或回执解析，不能用切换工作目录改变其含义。

可选的“拟合参数 JSON”是参数对象，留空使用公共 fitter 默认值：300 steps、seed 1234、lr 0.0003、weight_decay 0.01、batch_size 4、hidden 256、layers 2、heads 4、max_tokens 4096、alpha 1、y_identity_weight 1、x_identity_weight 0、x_identity_mask null、threads 2。例如：

```json
{"steps": 300, "seed": 1234, "lr": 0.0003, "batch_size": 4, "threads": 2}
```

仅接受上述 14 个字段。GUI 将它们映射到现有 CLI flags，不向 fitter 传不存在的 `--config`。未知键、错误类型、非有限数值、不兼容 hidden/heads 或缺少名称的 x identity mask 会被拒绝。浮点数按不受系统区域设置影响的格式传入。

新模式只在 CPU 上运行，不启动 H3 编码或 JEV，不读取 validation/test，也不执行 alpha 扫描。界面显示运行阶段和已用时；逐步 loss 与步数记录在输出目录的 `OPTIMIZATION.jsonl`。仅固定终点保存权重，完成后校验 `RESULT.json`、权重 SHA 与重载结果；训练完成不等于视频验收通过。

本模式**不支持断点续训**。停止只终止该 GUI 启动的当前 Python 进程，保留已写日志；重新运行必须选择新目录，已有空目录也不能复用。失败或停止时，即使留下权重文件也不会显示成功。旧四种训练模式及其 epoch 续训规则保持不变。

## 1. 先准备真实原生表示及来源

每对样本准备完整的 `x.txt`、`y.txt`、原生 `x.npy`、`y.npy` 和原生 tokenizer 对齐 JSON。X 是待纠正提示词，Y 是审核过的目标；身份、装备、能力、事件、特效与声音的变化必须由数据设计明确约束，不能以未经核实的增写冒充纠错。

数组必须是实际编码得到的有限 FP16/FP32 `[tokens, dim]`（也接受 batch=1）；真实 H3 训练维度为 5120。不通过 FP16 中间缓存伪造原生 FP32，不自动截断。编码器权重、关键代码、tokenizer、模式及输出维度应有来源记录。相同语义编码器的不同执行设备/实际输出精度可以保留各自 provenance；不能仅把不同编码器的标签写成一样来绕过检查，也不能把 FP16 与 FP32 声称为逐位等价。

`alignment.json` 的核心格式如下；ID 必须来自对应完整提示词的实际 tokenizer，不是字符位置或猜测：

```json
{
  "token_alignment": {
    "bad_ids": [0, 1, 2],
    "good_ids": [0, 3, 4, 2],
    "bad_text_sha256": "完整X原始UTF8字节的SHA256",
    "good_text_sha256": "完整Y原始UTF8字节的SHA256"
  }
}
```

上面的 ID 仅说明字段，不是可用于 H3 的样本。`tokenizer_vocab.json` 是原生 byte-level BPE 的 token→ID 词表。工具用该词表验证 ID 能逐字节还原原始 UTF-8；不支持凭空推断特殊 token、模板 token 或任意 tokenizer。若原生编码包含模板前后缀，必须提供与实际 token/表示逐项对应的完整文本与来源，不能静默丢掉这些 token。

## 2. 构建显式句段目标

在样本目录写 `build.json`：

```json
{
  "schema": 1,
  "kind": "sentence_target_input_v1",
  "purpose": "research_candidate",
  "source_split": "train",
  "pair_id": "work01_scene01",
  "expected_dim": 5120,
  "max_tokens": 2048,
  "x": {"path": "x.npy", "sha256": "文件SHA256", "prompt_sha256": "X文本SHA256"},
  "y": {"path": "y.npy", "sha256": "文件SHA256", "prompt_sha256": "Y文本SHA256"},
  "texts": {
    "x": {"path": "x.txt", "sha256": "X文本SHA256"},
    "y": {"path": "y.txt", "sha256": "Y文本SHA256"}
  },
  "alignment": {"path": "alignment.json", "sha256": "文件SHA256"},
  "tokenizer_vocab": {"path": "tokenizer_vocab.json", "sha256": "文件SHA256"},
  "blocks": [{
    "x_token_span": [10, 20], "y_token_span": [10, 24],
    "x_text": "X对应token段的完整原文", "y_text": "Y对应token段的完整原文"
  }],
  "prefix_token_span": [0, 10]
}
```

占位值需要替换成真实值。路径相对 `build.json`，SHA 使用文件原始字节；不要换行归一化后再算。NPZ/safetensors 输入额外指定 `key`，仅允许单对数据，不接受聚合 NPZ。可以添加 `raw_sha256` 绑定原生数组载荷。

跨度采用左闭右开 token 索引，可以有多个不同长度、按顺序且不重叠的块。`x_text/y_text` 必须精确等于对应 token 段；不能截断 UTF-8 字符。原 monotone transport 边不能跨越指定块边界，否则需重新检查并显式扩展边界。`prefix_token_span` 可省略；若提供，不得与目标句段重叠。

```powershell
python path/to/repo/tools/build_sentence_targets.py --manifest data/work01_scene01/build.json --output-dir data/work01_scene01/target
```

句内使用均匀单元交叠权重将完整 Y 句段 transport 到 X token 位置；句外保留重新计算的原 monotone T，不替换成 X。原生 X/Y 保持其实际 dtype，目标用 CPU FP32。产物为 `sentence_target.npz` 与 `TARGET_RECEIPT.json`，记录数组形状、精度、原始载荷 SHA、token/文本边界和所有来源哈希。构建前后重核来源；拒绝覆盖已有输出。

`training_admitted: false` 表示目标构建没有自动证明数据质量或视频有效性；目标可以作为显式实验训练候选，但仍需人工确认来源及任务合理性。之前被判歧义/错误的目标不能因重建文件就变成正例。默认 builder 最大 2048 token；超过时显式提高 `max_tokens`，不裁剪。

## 3. 生成 train manifest 并 dry-run

每个样本还需 `context.json` 绑定 pair/split、编码器身份、X/Y 文本与载荷哈希、真实输出精度。可用下面脚本从真实 receipt 生成上下文及单对训练 manifest；`encoder_id` 必须由你核实的模型/代码/tokenizer来源确定。下面只生成元数据，不生成训练表示。

```python
import hashlib, json
from pathlib import Path
base = Path("data/work01_scene01")
def digest(p): return hashlib.sha256(p.read_bytes()).hexdigest()
def save(p, v):
    with p.open("x", encoding="utf-8") as f: json.dump(v, f, ensure_ascii=False, indent=2)
def ref(name): return {"path": name, "sha256": digest(base / name)}
r = json.loads((base / "target/TARGET_RECEIPT.json").read_text(encoding="utf-8"))
context = {
    "pair_id": r["pair_id"], "split": "train",
    "encoder_id": "替换为已核实的共同语义编码器身份摘要",
    "source_precision": r["source_precision"],
    **{k: r[k] for k in ("prompt_x_sha256", "prompt_y_sha256", "x_raw_sha256", "y_raw_sha256")}
}
# 可继续保存 source_encoder_id、实际device、编码版本等真实provenance。
save(base / "context.json", context)
masks = {k: k for k, v in r["arrays"].items() if v["dtype"] == "bool"}
row = {
    "pair_id": r["pair_id"], "split": "train",
    "work_id": "work01", "group_id": "independent_scene_family01",
    "prompt_x": ref("x.txt"), "prompt_y": ref("y.txt"), "context": ref("context.json"),
    "target_receipt": ref("target/TARGET_RECEIPT.json"), "arrays": ref("target/sentence_target.npz"),
    "array_keys": {k: k for k in ("x", "y", "target")}, "masks": masks,
    "raw_sha256": {k: r["arrays"][k]["raw_sha256"] for k in ("x", "y", "target")},
    "region_weights": {"all": 1.0}
}
save(base / "fit.json", {"schema": 1, "kind": "explicit_train_target_manifest_v1",
    "evidence_class": "train_fit_probe", "pairs": [row]})
```

多对训练把审核好的行放入同一个 `pairs` 列表，所有行路径相对该训练 manifest。`masks` 必须列出 NPZ 中所有 mask；`monotone_target` 允许存在但不载入训练。`region_weights` 可用这些命名区域；区域重叠会按各自权重累加，不会自动消除重复。所有行要求共同 encoder identity 和 embedding dimension；重复 X 文本或相同 X 原始载荷拒绝。

```powershell
python path/to/repo/tools/fit_explicit_targets.py --manifest data/work01_scene01/fit.json --dry-run
```

dry-run 校验来源、训练划分、receipt、精度、数组有限性、mask 和长度；不会创建模型或优化器。val/test 行在打开数组之前拒绝。默认最大 4096 token，超过报错不截断。输入及 receipt 的相对路径分别相对所属 manifest/receipt；工具新生成的 receipt 会绑定解析后的绝对路径及代码 SHA。迁移机器或更新工具后，应从原始来源重新构建目标及绑定，不应盲目修改哈希跳过检查。

## 4. 显式运行 CPU 训练

```powershell
python path/to/repo/tools/fit_explicit_targets.py --manifest data/work01_scene01/fit.json --manifest-sha ACTUAL_MANIFEST_SHA256 --output runs/explicit_target_experiment01 --execute
```

默认设置与研究流程一致：300 optimizer updates、seed 1234、AdamW lr 0.0003/weight decay 0.01、batch 4、hidden 256、2 层、4 heads、2 CPU 线程。按原生不同长度逐对 microbatch，不做 padding 或截断。默认 alpha=1、per_token magnitude match、全 token、chunk=0、guard=false、auto_alpha=false；最终权重内保存 application contract，部署必须匹配。

损失将显式区域目标 MSE、默认权重1的 Y identity MSE，加上可选 X 保护项，再除以该对初始 target-X MSE（下限 1e-4）。X 保护默认权重0；启用需要显式 `--x-identity-mask`，且 dry-run 会报告它与句外 T 的目标冲突。不要把不相容的目标误当作免费保护。

训练固定导出最后一步，不使用 val/test 选模；`STEP_*.json` 是训练集表示诊断，`OPTIMIZATION.jsonl` 保留更新轨迹。导出前重核来源和源码，保存后通过公共 `load_bridge`/`apply_bridge_to_conditioning` 重载检查。输出目录必须全新，没有自动续跑/覆盖。只保存一份最终 Bridge 权重，不复制 H3 模型、私有数据或视频。

## 5. 接入真实 H3 验证

训练后运行时仅输入 X，加载学到的共享网络并执行前向；不能读取 Y、训练 NPZ、预计算 target，也不能按输入哈希查表。先确认实际 Bridge 输入、输出、Guider 输入和 metadata/token tags，再与原生 X 在同 seed、图、采样参数和模型下做视频对照。

验收必须包含完整视频及声音、角色装备/能力、动作接触与结果连续性、特效和画面退化；表示损失改善只是诊断。独立保留验证集与未见作品/场景家族，受控文字变体不能计为独立原作场景，不能依靠扩大文字对数量承诺效果。若训练样本内视频改善未成立，应先修正监督假设；不得据 loss 直接发布“有效模型”。

CPU 合成集成测试：`python -B tests/test_explicit_targets_public.py`。测试使用临时的低维随机数组和未具备 H3 意义的小权重，不读取真实数据或调用 GPU。
