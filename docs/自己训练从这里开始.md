# 用户自己训练：数据准备与界面填写

普通用户从“无评分偏好对：仅语义桥”开始。这个模式学习 H3 文本条件表示上的修正，不更新视频主模型或文本编码器，也不训练视频 LoRA。只需文本训练对，不要求先收集训练视频、图片或视频逐帧标注。

## 1. 准备环境与三个输入文件

- 保留完整训练器文件夹，包含 EXE、`python/`、`tools/`、`wushu_bridge/`、配置和说明。
- 准备支持 MiniMax H3 的 ComfyUI，以及与今后视频推理一致的 H3 文本编码器文件。训练器包不附带大型编码器。首次编码需加载编码器，实际内存需求取决于模型格式和电脑；只看桥权重小，不能推断编码也只需很少显存。
- 自己编写 `pairs.jsonl`，保存“较差描述／较好描述”。
- GUI默认自动生成分组文件，无需手写 `split_manifest.json`；数据制作时正确填写场景编号group_id即可。
- 选择训练参数文件。初次先用包内 `configs/preference_v1.json`，跑通后再另存配置修改。

首次不需要自己制作 NPZ、checkpoint 或 `.safetensors`。这些是编码与训练阶段的产物。

## 2. 怎么写好坏文本对

每对描述应围绕同一场景、人物、道具和目标动作。先决定一个要教给桥的明确问题，再写两种描述：

- `bad`：存在目标问题的较差描述，例如“绕到柱后”没有明确出入口、遮挡后错误换手、火焰来源归属含糊。
- `good`：清楚描述顺序、位置、对象归属和持续状态，纠正同一问题，保持无关设定一致。

例如，坏稿说“剑士绕柱躲过火球，再出现”；好稿明确“从柱左侧进入遮挡，火球从原站位掠过，从柱右侧再现且仍用右手持剑，火球熄灭后两人停住”。这类文本差异是训练目标；文字写得更长本身不等于更好。

使用动漫或游戏角色时，先核实角色原有外形、武器、能力和适用时期。不要把猜测的招式或增加新角色当成纠错。可以请 AI 起草文本对和 JSON，但要逐对审核，不能直接把生成行数当成数据质量。

尽量沿用接收者平时输入 H3 的完整提示词结构、语言和长度。可包含 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`；不要一边用短句，另一边无关地加入大量剧情与特效。

### JSONL 格式

UTF-8 文本；每一行是一个完整 JSON 对象，不要在文件最外面加 `[]`。字符串里的换行写成 `\n`，不要把一条 JSON 拆成多行。无评分模式省略 `bad_score`、`good_score`，不填 `null` 或虚构分数。

```json
{"id":"scene_001_v1","group_id":"scene_001","bad":"剑士绕到柱后躲开火球，然后重新出现。","good":"剑士右手持剑，从石柱左侧进入遮挡。法师的火球沿原站位掠过。剑士从石柱右侧再现，仍用右手持同一把剑；火球熄灭后两人停住。","pair_preference":"good","label_type":"authoring_rubric"}
```

- `id`：建议填写，每条记录唯一。
- `group_id`：同一原始场景的改写、翻译或变体共用一个编号。不同独立场景使用不同编号；不是简单给每行换一个编号。
- `bad` / `good`：非空且不同的文本。
- `pair_preference`：固定为 `good`。
- `label_type`：自行编写的文本偏好用 `authoring_rubric`。

软件训练入口最低需要 8 对，这是运行门槛，不是效果门槛。正式数据应覆盖多个独立场景和具体错误类型；重复同一个场景的措辞不会增加同等数量的独立证据。

包内 [格式示例](../examples/preference_starter/pairs.format-example.jsonl) 有 8 对原创文本，**只供格式教学和软件检查，不是已验证有效的训练集**。

## 3. 分组清单自动生成

GUI选择自己的JSONL并保持“自动（推荐）”，点击检查环境或开始训练即可。程序按group_id和共享文本生成约80%训练、10%验证、10%测试的关联场景组划分，保存到local/splits/，同一数据复用；续训读取原任务保存的清单，不重新划分。手动划分可取消勾选；真实视频反馈和token实验仍需显式分组。

以下格式和命令供手动设置或Agent使用，普通用户不用操作。

训练集用于学习，验证集用于选训练结果和参数，测试集用于最终检查。按场景组划分，训练、验证、测试都必须非空；每个 `group_id` 恰好出现一次，不漏掉，也不能同时出现在两个分区。

```json
{
  "schema": 1,
  "split_unit": "group_id",
  "splits": {
    "train": ["scene_001", "scene_002", "scene_003", "scene_004", "scene_005", "scene_006"],
    "validation": ["scene_007"],
    "test": ["scene_008"]
  }
}
```

不要直接把这八个示例编号套到自己的数据。分组文件里的编号必须与自己的 `pairs.jsonl` 完全对应。

不想手工整理，可在训练器根目录打开 PowerShell，替换下列两条路径后运行：

```powershell
.\python\python.exe examples\preference_starter\make_splits.py 'D:\MyBridge\pairs.jsonl' --output 'D:\MyBridge\split_manifest.json'
```

小工具要求至少 8 个可分开的场景关联组，生成约 80%／10%／10% 的场景组划分，具体行数随组大小变化。它保留同 `group_id` 和相同文本的关联关系，覆盖所有数据，不会覆写已有分组文件。仍需人工确认同源场景是否正确共用 `group_id`；它不能自动识别内容相似但文字不同的场景。编码后训练器还会检查相同 embedding 跨分区的问题。

## 4. 界面每项怎么填

以下 `D:\MyBridge` 只是路径示例，请换成自己的目录。

| 界面项目 | 用户应该填什么 |
|---|---|
| Python 环境 | 包内 `python\python.exe`；通常保持自动填写值。也可使用已经能运行 H3 的 ComfyUI Python，但需确保训练依赖齐全。 |
| ComfyUI 目录 | 支持 H3 且包含 `comfy` 文件夹的根目录；完整便携包自动填写的包内目录可先保留。不是 `custom_nodes` 或模型文件夹。 |
| H3 文本编码器 | 实际 H3 文本编码器权重文件，与视频部署的编码器及量化版本保持一致；不是 H3 视频主模型、Turbo LoRA 或 Semantic Bridge。 |
| 源训练对 JSONL | 自己准备的 `D:\MyBridge\pairs.jsonl`。 |
| 源编码数据 NPZ | **首次填一个尚不存在的输出文件路径**，例如 `D:\MyBridge\encoded\pairs_v1.npz`。程序会创建它；不是要求用户先选已有 NPZ。 |
| 训练输出目录 | 独立的新目录，例如 `D:\MyBridge\runs\run_001`；可保留界面自动生成的新路径。不要指向原模型目录。 |
| 训练参数 JSON | 初次选择包内 `configs\preference_v1.json`。这是常规偏好模式的起步配置，不保证最佳视频效果。 |
| 源偏好分组划分 | 保持“自动（推荐）”；检查/训练时自动生成并回填。手动划分才取消勾选后选择JSON。 |
| 实验准备数据目录 | 本模式不使用，保持灰色默认。 |
| 视频反馈证据目录 | 普通自行编写的文本对留空。 |
| 训练方式 | **无评分偏好对：仅语义桥**。 |
| 全变体 | 本常规模式不使用，保持默认。 |

### 训练参数文件需要怎么改

第一轮可直接用 `preference_v1.json`。它默认 Transformer `hidden=256`、`layers=2`、`heads=4`，`batch_size=8`，学习率 `0.0003`，最多 `150` 轮，`patience=12`，训练 alpha 采样范围 `0.05–0.35`，`magnitude_mode=none`。

需要调整时，先复制成自己的 JSON，再在“训练参数 JSON”里选这份副本：

- `batch_size`：若训练阶段显存不足，可从 8 降到 4 或 2。降低桥训练 batch 不解决首次加载大型文本编码器的内存需求。
- `bridge_epochs`：最大训练轮数；例如 60 是较短的试跑安排，不代表比 150 更优。
- `bridge_lr`：初次保留 `0.0003`，根据训练和验证再调整。
- 其他架构、损失、幅度和 alpha 项先保持同一套配置；改配方要新开运行目录。

GUI 的 validation 诊断会分别检查 `none`／`per_token`，不自动选择最佳推理 alpha。旧 Sentence75 的固定 `alpha=1.0` 不是所有新桥的通用设置。需要与本次训练／推理公式一致的幅度实验时，在独立配置和运行中设计，并用实际视频复核。

## 5. 按什么顺序操作

1. 填齐上表；点“检查环境”。此步检查依赖、数据与分组，不代表大型编码器已经成功加载，也不代表数据能改善视频。
2. 编码器需要使用显存时，选择其他生成任务空闲的时段，再点“开始训练”。程序依次检查文本、编码或核对已有缓存、训练语义桥、检查导出权重，并输出 validation 表征诊断。
3. 新数据集第一次编码会生成 NPZ、旁边的元数据和回执；复用时要一起保留。更换文本或编码器后选择新的 NPZ 路径，不要借用别人的缓存。
4. 训练中断后，保留同一组数据、配置、分组清单、软件环境和输出目录，再点“断点续训”。不要在旧目录中改数据继续跑。
5. 在输出目录取得 `bridge.safetensors`。复制并改成独立名称放到 `ComfyUI/models/semantic_bridge/t8_compat/`，在 T8 Bridge Config／Apply 中使用。
6. 用相同提示词、seed和视频采样配置比较开／关桥，观察动作顺序、空间、遮挡和对象归属。表征诊断与训练 loss 不能代替视频效果判断。

本流程不会自动训练视频、生成验收视频或覆盖已有发布模型。首次使用包内示例只能确认软件与文件格式，不能据此宣布得到有效模型。

## 6. 常见报错

- “找不到文件（Pairs）”：源训练对 JSONL 为空、文件不存在，或把 `.jsonl.txt` 当成了 `.jsonl`。
- 自动分组缺group_id或场景组不足：请让制作数据的Agent补齐场景编号或独立场景，不用手写分组JSON。手动模式才需选择清单。
- 分组覆盖／泄漏错误：漏了某些 `group_id`，重复分区，或相同／关联文本跨分区。
- 已有 NPZ 不匹配：数据或编码器变了，换一个新 NPZ 保存路径。
- CUDA 内存不足：区分首次编码器加载还是桥训练阶段；仅降低桥训练 batch 不能解决前者。

如需命令行、数据来源约束和更多实验模式，见 [偏好训练说明](preference-training.md) 与 [可复用训练器](可复用训练器.md)。

## 训练完成后：alpha到底怎么选

训练器会在`bridge.safetensors`旁自动生成`模型使用说明.md`和`inference_settings.json`。GUI完成后显示参数摘要，也可点“模型用法”；分发模型时把两份说明一并提供。JSON包含模型SHA-256，防止用错另一模型的说明。

- **固定契约**：明确写“固定alpha”，必须遵循权重设置。例如旧Sentence75固定1；token实验则遵循实际配置，不一定是1或0.12。
- **普通自训**：写“建议起点”，默认范围配方通常从0.12试用，并使用与训练公式一致的幅度模式；不是已验证最佳值。训练采样alpha范围不等于最佳视频强度，文本loss也不能选出最佳视频强度。
- **chunk_tokens=0**：不切块，整段送入桥；不是禁用token。跨token的Transformer切块会改变上下文。本包训练桥默认整段使用，不能照搬逐token社区MLP的256切块设置。

先按该模型说明填写整套T8参数，再做少量同提示词、同seed开/关桥对照。`none`和`per_token`会改变应用公式，也要看这份模型的说明，不只看alpha。

旧模型需要重新导出说明时可使用以下命令，不会重训或改写权重：

```powershell
.\python\python.exe tools\trainer.py usage --bridge '你的模型.safetensors' --output-dir 'local\model_usage'
```

无训练配方和固定契约的旧权重只能给出未校准的后备起点，不能自动推断其作者的最佳设置。已有模型卡或原作者记录优先核对。
