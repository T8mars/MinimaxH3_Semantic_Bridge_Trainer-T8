# 可复用训练器

Windows 用户可双击 `WushuBridge-Trainer.exe` 使用图形界面。
发给其他人请使用包含 Python 的整合包，见 [便携整合包](便携整合包.md)。
动漫战斗项目的配套 [MiniMax H3 视频提示词 Skill](../skills/minimax-h3-anime-battle-prompts/SKILL.md)
负责核实原作事实和写可评测的提示词；其中的 [A/B 验收模板](../skills/minimax-h3-anime-battle-prompts/references/ab-evaluation.md)
用于判断训练出的桥是否真改善视频。训练器本身不训练 H3 视频 LoRA。

新便携包不附带作者权重、676 对数据或 H3 编码器。下面有关这些文件的命令
仅在你另行取得并放入相应路径后适用。无评分偏好对请在 GUI 选择“仅语义桥”
模式，指定自己的 JSONL、group_id 划分 JSON 与训练配置；完整格式和流程见
[偏好训练说明](preference-training.md)。原数值评分模式仍训练桥和 JEV。

`tools/trainer.py` 提供独立命令行入口，不必在 ComfyUI 中搭训练节点。
编码阶段使用本地 ComfyUI 的真实 MiniMax H3 文本编码器；训练阶段只需
PyTorch、NumPy、safetensors。建议使用运行 H3 的同一个 Python 环境。

## 使用已有作者模型

若你已另行取得作者的两份 `.safetensors`，可放入 `models/wushu_bridge/`。
执行 `python tools/trainer.py verify` 可检查加载、前向计算及 metadata 保留。
这是兼容性检查，不代表视频质量验收。

若要在已取得的作者桥权重上继续训练**新的语义桥**，可使用独立新目录和
`--stage bridge --init-bridge <权重路径> --init-bridge-sha256 <文件SHA256>`。
训练器会核对文件哈希、架构、全部参数名和形状，并把参数复制到新模型；
优化器、学习率计划与混合精度状态从零开始。权重来源写进运行签名、报告和
导出模型，作者原文件不会被改写。初始化不能和 `--resume` 同时使用；
中断后用同一数据、配置、代码及普通 `--resume --stage bridge` 恢复新运行。
旧 676 对数值规则样本不应未经审核就与新文本偏好对混训。初始化与文本
表征指标都不能代替本地 H3 同提示词视频验收。

## 从镜像的 676 对重新训练

以下命令在仓库根目录运行。把 `<ComfyUI目录>`、`<编码器完整路径>` 替换为
真实路径。使用 PowerShell 时可先设 `$py = '你的Python完整路径'`，
将命令开头的 `python` 替换为 `& $py`。

```powershell
python tools/trainer.py inspect models/wushu_bridge/datasets/wushu_pairs_v1_pairs.jsonl --report local/pairs_inspection.json
python tools/trainer.py encode models/wushu_bridge/datasets/wushu_pairs_v1_pairs.jsonl --comfy-root '<ComfyUI目录>' --encoder '<编码器完整路径>' --output local/wushu_pairs.npz
python tools/trainer.py train local/wushu_pairs.npz --output runs/wushu_v1 --config configs/author_v1.json
python tools/trainer.py verify --bridge runs/wushu_v1/bridge.safetensors --judge runs/wushu_v1/judge.safetensors
python tools/trainer.py evaluate local/wushu_pairs.npz --run runs/wushu_v1 --device cuda
```

编码器可采用当前 ComfyUI 支持的 H3 权重格式。训练和部署应固定相同的编码器
文件及量化版本；5120 维相同不足以证明不同模型或量化格式等价。
文本编码缓存绑定权重 SHA256、ComfyUI 版本、编码实现、tokenizer 与截断设置。
同时绑定设备、CUDA、GPU型号和关键包版本；切换编码环境应另建数据集。
编码中断后重复原命令会读取已完成的缓存；输出数据集已存在时拒绝覆盖。
不要在另一项生成任务占满显存时启动编码。

训练只支持 T2V 文本训练对。Ref2VA 必须另采集包含真实参考 token 的
CONDITIONING 并设计对应训练集，不可把本文模型标为 Ref2VA 专用。

## 断点、数据与配方

```powershell
# 同一数据、代码、配置继续训练
python tools/trainer.py train local/wushu_pairs.npz --output runs/wushu_v1 --config configs/author_v1.json --resume
# 主动在第2轮末保存并停止，用来验证恢复
python tools/trainer.py train local/wushu_pairs.npz --output runs/resume_check --stop-after-epochs 2
# 使用自己的语料，沿用作者的抽取、降级和规则评分
python tools/trainer.py pairs --corpus '<语料文件或文件夹>' --output local/custom_pairs.jsonl
```

checkpoint 每个 epoch 原子写入，包含模型、最优权重、优化器、学习率计划、
混合精度状态、CPU/CUDA/NumPy 随机状态。异常发生在 epoch 中间时，从上一完整
epoch 重做。修改数据、配方、训练代码或运行环境会拒绝直接恢复，应另开输出目录。

`configs/author_v1.json` 采用作者报告的 Transformer 256/2/4、桥最多150轮、
评分头最多200轮、学习率3e-4/1e-3、anchor=0.15及alpha=0.05–0.35。
默认保留作者未做幅度对齐的训练公式。另存配置并将 `magnitude_mode` 改成
`per_token` 可做与推理幅度处理一致的实验；它不是作者原始配方。
桥的早停改善门槛可由 `bridge_val_min_delta` 设置，默认 `1e-5` 以兼容旧运行；
原值很小时，可在新运行中单独试 `1e-7`。训练报告分别记录按门槛实际导出的
`best_val_loss` / `selected_best_val_epoch` 和观测到的 `raw_best_val_loss` /
`raw_best_val_epoch`，避免把两者混为一谈。`semantic_pool_scope` 默认
`all_valid_tokens`；研究用 `exclude_shared_first` 仅在每对编码序列的第一个
H3 token 数值相同（允许最大绝对差 ≤0.002 且差值 RMS/原向量 RMS ≤1e-6）
且长度至少为2时允许，它只改变训练与验证的语义池化，
推理仍处理完整 conditioning。使用任一实验选项应新开输出目录并在同一
验证分组和真实视频中对照；文本余弦变化本身不证明效果。

可选 `semantic_objective: "vector_target_v1"` 是研究中的 Semantic Bridge
目标函数：在真实 H3 文本条件上拟合正负提示词池化向量之差的方向与长度，
保留 anchor，但不沿用作者的方向余弦目标。默认仍为
`direction_cosine_v1`。新目标按自身 validation loss 早停，导出报告标记
`test_deferred`，不自动查看 test；它尚不能保证已完整写好的视频提示词或
生成视频获益。使用此选项须另开运行目录，完成同提示词真实 H3 视频对照后
才能决定是否采用该权重。

研究选项 `semantic_objective: "deployed_vector_v1"` 针对实际部署的
`alpha=.12`、`magnitude_mode: "per_token"` 混合结果训练。配置必须同时设置
`alpha_min: 0.12`、`alpha_max: 0.12`、`residual_skip: true` 和
`anchor_weight: 0`。目标是让混合后的池化位移达到好坏提示词池化差的
`deployed_target_fraction`（默认 0.10），并用
`deployed_good_identity_weight`（默认 1.0）惩罚好输入经同一桥处理后的
token 漂移。两个损失都按每对目标位移能量归一化；近零位移对会被拒绝。
验证集用同样的 `.12/per_token` 目标损失选权重，报告推迟 test，导出权重
带固定部署参数契约。两个新参数只适用于此目标；它们不是视频效果指标。

本训练器修复 padding mask，按关联文本/相同 embedding/显式 `group_id`
划分约70%训练、10%验证、10%校准、10%测试。每对正负例始终在同一区间。
未知的同视频或中英译文同源关系仍需人工补充 `group_id`。
JSONL 的规则软标签保留原值，不能把所有 good 强改成1、bad改成0。
由此得到的验证指标与作者的随机单样本切分指标不可直接比较。

## 交付物与验收

新版启动器另提供“实验：等长逐 token 对齐 + identity”与“实验：变长 token
单调映射 + identity”模式，默认参数分别为 `configs/experimental_aligned_token_v1.json`
和 `configs/experimental_monotone_token_v1.json`。源 JSONL、源编码 NPZ、编码器和
原始分组清单仍填写原文件；对齐数据另存到独立目录。界面会准备可对齐样本，
使用派生数据及分组只训练语义桥，再做固定强度的 `per_token` validation
辅助诊断。该诊断不是训练时的纠正加保持损失，也不证明视频改善。
准备默认每个 `group_id` 只保留一条确定性样本；若已审核同组的多条
变体并决定全部参与，图形界面可在实验训练方式右侧勾选“全变体”，命令行可显式加
`--selection-policy all_rows`。准备回执会分别
列出可用数、实际保留数和各分区对数。多条变体仍属于同一场景组，不可把行数
当成独立场景数。复用准备目录时会核对选择策略；切换策略需新建准备目录及运行目录。
逐 token 报告的 `token_target` 另列坏稿校正误差、好稿 identity 误差、
逐对校正改善比例及固定 alpha/`per_token` 约束下的理论最小误差。
新导出的逐 token identity 权重会记录训练时的固定应用契约。ComfyUI 节点和
`trainer.py verify` 必须使用该 alpha、`per_token`、完整 token 范围和未分块推理；
推理默认 0.12 不会覆盖权重内的训练值，设置不一致会明确报错。
下界只表示当前 CONDITIONING 混合形式的可达范围，不是网络训练结果或视频质量分。
此模式不做 `none` 扫描、不训练评分头、不自动读取 test 质量指标。
已有准备目录先核对源文件、产物、准备源码与 tokenizer 回执；续训复用原目录，
并继续核对训练运行签名。旧 EXE 不会自动增加功能，当前根目录 EXE 已重新编译并通过合成自检，
最终分发版须待模型效果验收。具体命令及数据要求见 `preference-training.md`。
变长路径保留源 token 数，不是视频 LoRA；当前草稿尚无独立视频验收标签，
不能作为效果证明。

若 JSONL 的 `label_type` 是 `video_feedback_v1`，启动器中必须填写“视频反馈证据目录”。
该目录存放与训练对绑定的私有冻结计划、实际 H3 媒体完整性回执和双 seed、
双独立评审的完整声画结论；检查、编码、实验准备和训练都会再次验证文件哈希。
普通 `authoring_rubric` 文本偏好对将此栏留空。只有视频反馈回执通过严格准入，
才可把它当视频来源的训练偏好；静帧、文本改写、合成软件测试均不符合此条件。
作品的多场景对会保留，并按整个作品分组划分。当前动漫战斗桥仍处于固定训练与独立验收阶段；
尚无通过完整声画准入的视频反馈标签，也没有经过最终视频效果验收的新桥权重或最终整合包。

常规数值评分和无评分偏好模式都会输出 `run.json`、`splits.json`、每轮历史、断点和
`bridge.safetensors`。**仅语义桥**偏好模式不训练也不输出 `judge.safetensors`，
图形界面只自动生成 validation 的 `none` / `per_token` 诊断，不替用户选强度，
也不自动运行 test。旧数值评分模式才另输出 `judge.safetensors` 和评分报告；
它的校准只用 calibration 分区，测试集不参与早停或校准。评分头的 AUC、
ECE、pairwise 排名只描述它与规则标签的关系，不是成片合格概率。
桥的 gain/drift 与 `representation_gate_passed` 也只是文本表征检查。

先做相同提示词、seed、编码器、采样设置的无桥/作者版/重训版视频A/B，
再决定是否使用重训版。比较攻防接续、距离和接触点、命中反馈、结局以及人物保持。
本项目当前候选权重只有本地 ComfyUI 可加载，因此它的桥开/关视频对照须在本地完成；
不把无法加载该权重的在线生成结果算作桥臂。多拍顺序、空间换位、遮挡后身份与
持续后果是主要语义指标；特效观感及音频另记，不由语义桥单独保证。
对照时固定推理节点 `chunk_tokens=0`，并逐臂记录编码器权重 SHA256；
跨段推理会重置位置上下文，不应混入同一次桥效果对照。
训练完成不自动替换 ComfyUI 模型。使用最新版 [T8 推理节点](https://github.com/T8mars/comfyui-minimax-h3-audio-T8) 时，本训练器导出的 `trans`／`mlp` 桥均可加载；以不同文件名复制到
`ComfyUI/models/semantic_bridge/`，保留旧模型作对照。本仓库包内的 `models/wushu_bridge/` 是训练资料／发布物存放位置，不是 T8 节点的扫描目录；本次动漫战斗权重的确切用法见[便携包说明](便携整合包.md#将-semantic-bridge-接入现有-comfyui)。

本地 `roadmap.md`、`local/`、`runs/` 均排除 Git 和插件打包。

## 检查

```powershell
python -m pytest tests -q
python tools/trainer.py --help
```

测试中的随机 embedding 只验证软件契约，不是 H3 训练成果。

Windows 便携包使用 `WushuBridge-Trainer.exe`，默认选择“仅语义桥”偏好训练；须浏览选择自己的 JSONL、分组划分、H3 编码器及新输出目录。
源码仓库的 `Train-WushuBridge.ps1` 是旧数值评分流程入口，不随便携包分发。
现有数据集会核对配对清单、编码器、数据文件的SHA256；不匹配时要求另选输出路径。
训练器需要PyTorch>=2.3，参考 `requirements-training.txt`，优先复用已有可用环境。
