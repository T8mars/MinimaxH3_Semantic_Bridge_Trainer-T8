# Windows 便携训练器

将 Release 分卷合并并解压到有足够剩余空间的位置，
双击根目录的 **WushuBridge-Trainer.exe**。不要只复制 EXE。

整合包自带 Python 3.10、PyTorch 2.7.0 + CUDA 12.8 运行库、训练依赖、
ComfyUI 文本编码所需源码。版本以 PORTABLE_MANIFEST.json 为准。
默认构建不附带权重、676 对数据、其他用户数据或训练输出。本次实验版权重通过下文的显式选项单独选入；作者权重始终不附带。实验版模型卡会明确写出十组中 2 胜、8 平、0 明显回退，低于先前的 3 胜目标；不要把它称为已达标模型。
单独训练不需要另外安装 Python、Git、CUDA Toolkit 或整套 ComfyUI。
要在 H3 工作流里使用训练出的桥，接收者需已有可工作的 ComfyUI 与 MiniMax H3 节点。
需要复现本项目的四步本地视频对照时，还须在接收者的**视频生成用 ComfyUI**
另装 [KJNodes](https://github.com/kijai/ComfyUI-KJNodes) 与独立的
[ComfyUI-SolAttn_triton](https://github.com/kijai/ComfyUI-SolAttn_triton)，
并把 LightX2V 的 `minimax_h3_fl2v_turbo_4step_v1.2_768p_comfyui_bf16.safetensors`
放入该 ComfyUI 的 `models/loras/`。模型链为 H3 → Turbo LoRA →
`MiniMaxH3SigmaShift` → KJ `PathchSageAttentionKJ` → 独立 `SolAttnPatch`
→ guider/scheduler；文本链仍是 H3 编码 → Semantic Bridge → guider。
两条链接点不同，Sol 节点和四步 Turbo 不属于便携**训练器**的依赖或桥权重。
接收者应使用自己 ComfyUI 的 Python 检查 Triton/GPU 兼容性；
不能把便携训练器的 Python 目录直接当作视频生成环境。
需要 Windows x64 和系统 .NET Framework 4.8。原生 H3 编码及 GPU 训练模式还需要适配显卡的 NVIDIA 驱动；实验性显式目标拟合模式仅使用 CPU，但它要求你已准备好目标清单和原生编码数据。CUDA 运行库不能替代显卡驱动。

## 首次使用

1. 双击 EXE，Python 与 ComfyUI 路径会指向包内目录。
2. 选择训练模式：数值评分模式保留原来的桥 + JEV 流程；无评分偏好模式仅训练桥。
   自备训练对 JSONL；偏好模式还必须选择覆盖所有 group_id 的划分 JSON。
   点击“检查环境”，检查依赖、GPU、参数、训练对、划分和编码模块。
3. 将兼容 H3 的文本编码器 `.safetensors` 放到 `models/text_encoders/`，
   或通过“H3 文本编码器”的“浏览”选择其他位置的文件。大型编码器权重不在本包中。
4. 确认编码器路径、训练对、NPZ 保存位置、独立训练输出目录及参数 JSON。
5. 在显卡空闲时点击“开始训练”。现有 NPZ 会核对原训练对和编码器哈希，
   不存在时先编码。数值评分模式训练桥和评分头；偏好模式只训练桥，
   验证后分别写 none/per_token 的 validation 诊断，不自动选参或使用测试集。
6. 完成后点击“查看输出”，偏好模式模型为 `bridge.safetensors`；数值评分模式另有 `judge.safetensors`。

## 将 Semantic Bridge 接入现有 ComfyUI

视频推理请安装 [comfyui-minimax-h3-audio-T8](https://github.com/T8mars/comfyui-minimax-h3-audio-T8) 的**最新 GitHub 源码**；它需要现有可正常出片的 ComfyUI/H3 环境。便携训练器内的 `ComfyUI/` 仅是编码所需源码，不是完整视频推理安装。包内 `plugin/ComfyUI-H3-WushuBridge/` 是旧接线实现，不是本次模型推荐使用的 T8 节点。

从 [模型仓库](https://huggingface.co/t8star/semantic_bridge_T8-comic-combat) 下载 `semantic_bridge_T8_comic_combat.safetensors`，放到接收者 ComfyUI 的 `models/semantic_bridge/t8_compat/`，重启 ComfyUI 并刷新网页。发行包内已选模型仍保存在包自身的 `models/wushu_bridge/semantic_bridge_release.safetensors`，该路径只是**包内存放位置**；如使用此同一权重，也须把它复制到接收者的 `models/semantic_bridge/t8_compat/`。包内 `MODEL_CARD.json` 记录权重和验证信息。新训练出的 `bridge.safetensors` 也放到接收者的 `models/semantic_bridge/`，但 T8 节点能否加载取决于其权重架构；目前已验证本次发布的动漫战斗 Transformer 权重与 T8 最新源码兼容。

在普通 H3 工作流中，使用 **H3 Semantic Bridge / 模型与设置 (T8 EXP)** 选择模型，将其 `semantic_bridge` 接到 **H3 Semantic Bridge / 应用条件 (T8 EXP)**；再将原生 H3 `CONDITIONING → 应用条件 → 原采样条件输入`。Relay 或内循环工作流应使用其内置 `semantic_bridge` 输入，只应用一次。对本次动漫战斗权重，设置 `alpha=1.0`、`magnitude_match=per_token`、`token_scope=all_tokens`、`chunk_tokens=0`；这些是权重内固定契约，T8 节点会拒绝不一致的设置。其他自训权重按各自模型卡设置。语义桥不是视频 LoRA，不放入 `models/loras/`。

训练和部署须使用同一份 H3 文本编码器。插件加载成功、数值输出正常只说明
接线与权重可用；实际改善仍要用同提示词、同种子、同采样设置的 H3 视频对照验证。

此便携训练器只训练 **Semantic Bridge 文本条件适配权重**（可选旧数值评分模式的 JEV 头）。视频 LoRA 研发工具与文档不属于最终便携包；历史 v5 研究包曾携带这些源码，仅供区分旧版本。训练器产生的 `bridge.safetensors` 不能称为 H3 视频 LoRA，仍须在实际 H3 工作流里做同提示词、同种子的视频 A/B 才能判断效果。

配套的 MiniMax H3 视频提示词 Skill 在 `skills/minimax-h3-anime-battle-prompts/`，最终整合包会携带它。使用 Codex 时，把**整个 Skill 文件夹**复制到自己的 Codex skills 目录，重启或刷新技能列表后再调用；它依赖可访问的一手原作资料核实角色与招式。Skill 可以独立写提示词，但文字本身不代表 H3 已正确生成，效果仍按真实视频验收。
独立的 `handoff/` 文件夹列出模型、插件、训练器与 Skill 的位置，并给接手制作视频提示词 Skill 的 Agent 一份任务书；模型效果和推理参数仍以实际发布模型卡为准。

这次实测使用 RTX 5090 Laptop、约 24GB 显存及 NVFP4 H3 编码器。
换用不同编码器、精度或硬件会改变内存需求和训练结果；不能仅凭 5120 维相同
就认为编码分布一致。训练和实际部署应使用同一个编码器文件。

## 参数和恢复

包内还提供实验性显式句段目标入口：`tools/build_sentence_targets.py` 与
`tools/fit_explicit_targets.py`，按 `docs/精确目标训练.md` 使用包内 `python/python.exe`
执行。它们保留真实原生编码精度、核对句段和来源哈希，训练 Semantic Bridge。
更新后的 EXE 提供“实验：显式句段目标拟合（CPU，仅语义桥）”：选择已构建的
train 目标清单、新输出目录和可选拟合参数 JSON。“检查目标”默认只做 CPU dry-run；
“开始训练”先校验再用相同参数执行。目标构建仍使用命令行 builder，GUI 不自动编码或
认定目标质量。此模式仅保存最终权重，不支持断点续训；停止后重跑必须使用新的不存在目录。
旧四种模式及其 epoch 续训行为不变。EXE 必须与包内 Python、tools 和源码一起保留。
训练完成和可加载只说明流程跑通，仍需实际 H3 视频对照验收。

当前启动器源码提供“实验：等长逐 token 对齐 + identity”和“实验：变长 token
单调映射 + identity”两个选项，分别配套 `configs/experimental_aligned_token_v1.json`
与 `configs/experimental_monotone_token_v1.json`。两种模式均需单独的实验准备数据目录，
其余输入字段保持原始数据；准备成功后自动用派生 NPZ 和分组训练。
已有准备目录及断点恢复均校验原始输入和回执，避免混用缓存。
它只做固定 alpha / per_token 的 validation 辅助诊断，不自动选强度或验证视频效果。
源码和本地 EXE 自检已验证，旧整合包不含此更新；本次实验版统一构建后以清单中的文件哈希为准。
变长模式仅解决文本 CONDITIONING 长度差异；当前作者编写的训练对没有视频验收标签，
不能据此宣称视频效果改善。

使用 `video_feedback_v1` 训练对时，还须在“视频反馈证据目录”选择自己的私有证据根目录；
启动器将其传给检查、编码、准备和训练阶段，逐次核对冻结提示词、媒体完整性和
双 seed 双评审完整声画回执。普通作者编写的偏好对留空即可。当前本地正向先导
尚无准入标签；不能仅凭文本作者判断、静帧或训练损失声称成片效果。

- 数值评分模式默认采用 `configs/author_v1.json`，偏好模式采用 `configs/preference_v1.json`。需要调整 batch、epoch、学习率等时，
  复制该文件并修改，再在界面选择新 JSON。完整字段说明见“可复用训练器.md”。
  分发包只附带这些正式入口及两个已标注实验模式的示例配置；本机未通过视频验收的研究配置不随包分发。
- “停止任务”终止本次 Python 进程。已完成的文本缓存及完整 epoch 断点保留。
- 编码中断时可以重新点击“开始训练”；编码完成后训练若已建立 `run.json`，
  则选中原训练目录并点击“断点续训”。训练从上一个完整 epoch 恢复。
- 新实验点击“新输出目录”，避免覆盖已完成的实验或作者权重。
- 修改数据、训练源码、配置或环境后，请新开训练，不能强行续接原断点。
- `local/launcher_logs/` 保存完整日志和实际 CLI 命令计划 JSON；`local/launcher.settings.xml` 保存本机路径。

## 分发和内容边界

将构建得到的完整 ZIP 发给接收者。不要把自己使用后的目录直接重新压缩：
`local/`、`runs/`、`roadmap.md`、个人设置、缓存和训练输出不属于分发内容。
许可证随包保留。作者权重、公开 676 对训练集及本地研究记录均不在新包中；只有经真实视频对照并由模型卡如实标出结论的一个新 Semantic Bridge 权重可以入包。本次结论为有限收益实验版，未达到之前的 30% 目标。
旧整合包不会被覆盖；请勿把旧包中的数据混入新分发包。

`PORTABLE_MANIFEST.json` 列出依赖版本和源码版本；第三方许可证保留在 Python
标准目录、各依赖的 `.dist-info` 目录和 `ComfyUI/LICENSE` 中。
EXE 只是图形启动器，实际训练由包内 Python 执行；它不需要管理员权限。

软件检查、随机输入测试和训练指标均不能证明生成视频的质量。
在正式采用新模型前，仍需做固定提示词、种子和采样参数的视频 A/B。

## 从源码重新构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_launcher.ps1
# 使用已验证、含全部所需依赖的 Windows Python 环境执行：
python tools/build_portable.py --comfy-root '<ComfyUI源码目录>' --output dist/WushuBridge-Portable-Preference
# 验证便携环境之后再压缩：
python tools/build_portable.py --comfy-root '<ComfyUI源码目录>' --output dist/WushuBridge-Portable-Preference --archive-only --zip dist/WushuBridge-Portable-Preference-Windows.zip
```

构建器拒绝覆盖非空输出目录；可用 `--launcher <新 EXE 路径>` 选择独立编译的启动器。
构建器按安装包元数据复制依赖闭包，拒绝未经审查的 `.pth` 启动钩子，
不复制整个个人 Python 环境。后续新增依赖时需重新验证独立导入和实际运行。

完成同提示词、同种子、同采样设置的 H3 成片 A/B 评审之后，才准备一个不含本机路径的
`MODEL_CARD.json`，例如：

```json
{
  "schema": 1,
  "model_id": "anime-battle-semantic-bridge-v1",
  "weight_sha256": "<所选 bridge.safetensors 的 64 位小写 SHA-256>",
  "encoder_sha256": "<训练与部署共用 H3 文本编码器的 SHA-256>",
  "training_report_sha256": "<训练报告的 SHA-256>",
  "video_ab_report_sha256": "<H3 成片 A/B 验收报告的 SHA-256>",
  "video_ab_protocol": "same_prompt_same_seed_h3_video_ab",
  "video_ab_outcome": "limited_evidence",
  "video_ab_observation": {"pairs": 10, "relative_wins": 2, "ties": 8,
    "material_regressions": 0, "prior_target_wins": 3,
    "cohorts": "old 3 exposed development pairs plus 7 new accelerated pairs",
    "review_limit": "ordered frames only; normal-speed playback and audio not assessed"},
  "inference": {"alpha": 1.0, "magnitude_match": "per_token",
                "token_span": "all", "tail_ratio": 1.0, "chunk_tokens": 0,
                "allow_dim_mismatch": false, "auto_alpha": false, "guard": false}
}
```

卡片中的 `alpha` 与 `magnitude_match` 应写入实际成片验收时使用的值；示例值不是推荐值。
`magnitude_match` 只能是插件接受的 `per_token`、`global` 或 `none` 字符串。
卡片固定 `token_span=all`、`tail_ratio=1.0`、`chunk_tokens=0`、`allow_dim_mismatch=false`，
与本次 T2V 验收路径一致；设备仍由接收者运行环境选择。
构建器核验卡片格式、文件哈希、权重是否能作为 5120 维 H3 Semantic Bridge 严格加载，
并拒绝两份已知作者权重。构建时还须提供本地训练报告和 H3 成片 A/B 报告原文件以核对卡片哈希；
报告不会入包。哈希校验不能代替人工或独立评审判断视频质量。
最终构建时添加：

```powershell
python tools/build_portable.py --comfy-root '<ComfyUI源码目录>' --output '<全新空目录>' --release-weight '<已验收的新bridge.safetensors>' --release-model-card '<已核对的MODEL_CARD.json>' --release-training-report '<训练报告>' --release-video-ab-report '<H3成片A/B验收报告>'
```

发布权重固定放在 `models/wushu_bridge/semantic_bridge_release.safetensors`；发布卡固定放在
`models/wushu_bridge/MODEL_CARD.json`。`PORTABLE_MANIFEST.json` 再次记录两者精确 SHA-256，
封存后任何改动都会让 `--archive-only` 拒绝压缩。未同时提供四个发布选项时仍生成无权重包；
只提供其中一部分会被拒绝。
